# OwySync: руководство пользователя

[English version](user-guide.md)

OwySync синхронизирует один каталог в одну сторону: с **Windows-машины (local)** на **Unix-сервер по SSH (remote)**. Он сделан для сценария «исходный код → dev-сервер»: деревья на 10–200 тыс. файлов, частые мелкие правки, быстрая доставка изменений. Поставляется одним файлом `owysync.exe`: не нужны ни Cygwin, ни Perl, ни rsync, и на сервер ничего не устанавливается.

## Как это работает

1. При старте OwySync выполняет проверки (см. [`owysync check`](#owysync-check)), затем **полный resync**: обходит оба дерева, сравнивает их и приводит remote в соответствие с local. Источник истины — только local: всё на remote, чего нет в local и что не попадает под исключения, **удаляется**.
2. Затем включается **live-режим**: OwySync следит за локальным каталогом и отправляет каждое изменение на сервер примерно за секунду.
3. При обрыве соединения OwySync переподключается и снова выполняет полный resync.

Файлы сравниваются по **типу, размеру и времени изменения** (с точностью до секунды). Содержимое и права не сравниваются.

## Требования

**Локальная сторона**

- Windows 10/11, amd64 или arm64.
- Синхронизируемый каталог должен лежать на локальном диске (NTFS/ReFS). Сетевые диски и `\\wsl$\...` не поддерживаются: Windows ненадёжно сообщает об изменениях на них.

**Удалённая сторона**

- Linux (GNU coreutils или BusyBox) или FreeBSD. macOS не поддерживается.
- Доступ по SSH с полноценным shell и подсистемой SFTP. Ограниченные оболочки (`rbash`, `git-shell`, `ForceCommand`) и учётные записи только с SFTP не подходят.
- Стандартные утилиты: `sh`, `find` (с `-mindepth` и `-print0`), `xargs -0`, `stat` (GNU/BusyBox `stat -c` или BSD `stat -f`), `tar`, `rm`, `rmdir`. В обычной установке Linux или FreeBSD они есть.
- Файловая система под удалённым каталогом должна учитывать регистр (см. [Ограничения](#ограничения)).

## Установка

Положите `owysync.exe` в любой каталог из `PATH`. Установщика нет. Проверка:

```bat
owysync version
```

Для сборки из исходников нужен Go (версия указана в `go.mod`):

```bat
go build -ldflags "-X main.version=0.1.0" -o owysync.exe ./cmd/owysync
```

## Быстрый старт

1. Убедитесь, что обычный `ssh` входит на сервер без запроса пароля (см. [Настройка SSH](#настройка-ssh)):

   ```bat
   ssh user@dev.example.com
   ```

2. Инициализируйте каталог проекта:

   ```bat
   cd C:\work\myproject
   owysync init
   ```

   Init спросит хост, пользователя и абсолютный удалённый путь. Он запишет `.owysync\config` и `.owysync\ignore`, подключится к серверу и подготовит удалённый каталог.

3. **Отредактируйте `.owysync\ignore` до первой синхронизации.** Первая синхронизация удаляет на remote всё, чего нет в local и что не исключено: `node_modules`, загрузки, логи, сгенерированные файлы.

4. Посмотрите, что сделает первая синхронизация:

   ```bat
   owysync sync --once --dry-run
   ```

5. Запустите синхронизацию:

   ```bat
   owysync sync
   ```

   Остановка — Ctrl+C.

## Команды

Первым аргументом всегда идёт команда. Каждая команда, кроме `help` и `version`, принимает необязательный путь к локальному каталогу. Без него используется текущий каталог. Относительный путь отсчитывается от текущего каталога. Каталог должен существовать. `.owysync\` ищется только в нём, без подъёма к родителям. Флаги можно ставить до и после пути.

| Команда | Что делает |
| --- | --- |
| `owysync sync [путь]` | Полный resync, затем live-режим до Ctrl+C |
| `owysync sync --once [путь]` | Только полный resync. Код возврата 0 — успех |
| `owysync sync --once --dry-run [путь]` | Печатает план операций и итоговую строку. Ничего не меняет |
| `owysync init [путь]` | Диалоговая настройка |
| `owysync init --remote [путь]` | Только удалённая часть настройки, для уже существующего локального конфига |
| `owysync check [путь]` | Проверка настройки без записи |
| `owysync version` | Печатает версию |
| `owysync help` | Печатает версию и краткую справку. То же, что `owysync` без аргументов или `owysync --help` |
| `owysync sync -v [путь]` | Дополнительно печатает каждую операцию полного resync |

`--dry-run` работает только вместе с `--once`.

**Ctrl+C** прерывает выполняемые операции и сразу завершает работу. Достаточно одного нажатия. Временные файлы, оставшиеся на сервере, убираются при следующем запуске.

### `owysync init`

1. Завершается с ошибкой, если в каталоге уже есть `.owysync\`. В этом случае правьте `.owysync\config` напрямую и проверяйте его через `owysync check`.
2. Спрашивает:
   - хост (`host` или `host:port`);
   - пользователя (по умолчанию — имя пользователя Windows);
   - абсолютный удалённый путь.

   Ctrl+C во время диалога ничего не записывает.
3. Записывает `.owysync\config` (введённые значения и остальные ключи, закомментированные со значениями по умолчанию) и шаблон `.owysync\ignore`.
4. Подключается и выполняет проверки 1–6 из `owysync check`. При неудаче конфиг сохраняется. Исправьте его вручную (например, задайте `identity_file` или `port`), проверьте через `owysync check` и завершите настройку командой `owysync init --remote`.
5. Готовит удалённый каталог. Каждый вопрос по умолчанию отвечается «нет»:

   | Удалённый каталог | Что делает init |
   | --- | --- |
   | Не существует | Предлагает создать его вместе с родительскими каталогами |
   | Существует, маркера OwySync нет | Показывает число объектов и до 10 имён верхнего уровня, предупреждает, что первая синхронизация удалит всё, чего нет в local и что не исключено, и спрашивает, инициализировать ли каталог |
   | Существует, маркер уже есть | Предупреждает, что в каталог, вероятно, уже синхронизирует другой локальный каталог (два источника будут затирать друг друга), и спрашивает, подключиться ли к нему. Ничего не записывает |

   При инициализации в удалённом каталоге создаётся `.owysync/` с пустым файлом-маркером `remote` и каталогом `tmp/`.

Init нужна консоль. С перенаправленным вводом он не работает, неинтерактивного режима нет.

### `owysync check`

Ничего не пишет ни на одной стороне. Выполняет проверки по порядку, для каждой печатает `ok` или `FAIL: причина` и останавливается на первой неудаче:

1. `.owysync\config` и `.owysync\ignore` существуют и разбираются.
2. TCP-соединение с `host:port`.
3. Ключ хоста есть в `known_hosts` и совпадает.
4. Аутентификация (ssh-agent, затем `identity_file`).
5. Работает подсистема SFTP.
6. Доступен shell, определён вариант `stat` (выводится), есть `tar`.
7. `remote_root` существует и является каталогом.
8. Есть маркер `.owysync/remote`.

Право на запись не проверяется, потому что для этого пришлось бы писать. Код возврата 0 — все проверки прошли. Синхронизация выполняет те же проверки перед стартом и печатает их, только если какая-то не прошла.

## Конфигурация: `.owysync/config`

Строки вида `key = value`. Строки, начинающиеся с `#`, — комментарии. Каждый ключ можно указать только один раз. Неизвестный ключ или пустое значение — ошибка.

| Ключ | Обязателен | По умолчанию | Значение |
| --- | --- | --- | --- |
| `host` | да | — | Имя или адрес сервера. Допускаются `host:port` и `[ipv6]:port`. Не задавайте порт одновременно в `host` и в `port` |
| `port` | | `22` | Порт SSH |
| `user` | да | — | Пользователь на сервере |
| `identity_file` | | — | Полный путь к закрытому ключу, например `C:\Users\you\.ssh\id_ed25519`. Без него используются только ключи из ssh-agent |
| `remote_root` | да | — | Абсолютный удалённый путь (начинается с `/`). Может быть symlink на каталог |
| `file_mode` | | `0644` | Права (восьмеричные) для новых файлов |
| `dir_mode` | | `0755` | Права (восьмеричные) для новых каталогов |
| `debounce_ms` | | `100` | Сколько миллисекунд локальный каталог должен «молчать», прежде чем пачка изменений уйдёт на сервер |
| `mtime_window` | | `0` | Допуск в секундах при сравнении времени изменения. Для локального каталога на FAT укажите `2` |
| `concurrency` | | `64` | Сколько SFTP-операций выполняется одновременно |
| `bulk_threshold` | | `100` | С какого числа загрузок или удалений в пачке включается пакетный режим (см. ниже). `0` — отключить |

Пример:

```ini
host = dev.example.com
user = alice
remote_root = /home/alice/www/myproject
identity_file = C:\Users\alice\.ssh\id_ed25519
```

`config` и `ignore` читаются при старте. Если их изменить во время работы, OwySync выведет предупреждение, а изменения вступят в силу после перезапуска.

## Настройка SSH

У OwySync собственный SSH-клиент. Он **не** читает `~/.ssh/config` и не поддерживает пароли и Pageant.

- **Аутентификация.** Сначала OwySync пробует ключи из агента Windows OpenSSH (служба `ssh-agent`), затем `identity_file`. Защищённый паролем `identity_file` напрямую использовать нельзя: добавьте такой ключ в агент.

  Один раз запустите агент (в PowerShell от имени администратора) и добавьте ключ:

  ```powershell
  Get-Service ssh-agent | Set-Service -StartupType Automatic
  Start-Service ssh-agent
  ssh-add $env:USERPROFILE\.ssh\id_ed25519
  ```

- **Ключ хоста.** Ключ сервера сверяется с `%USERPROFILE%\.ssh\known_hosts`. Сам OwySync неизвестный ключ никогда не принимает. Подключитесь один раз обычным ssh и подтвердите ключ:

  ```bat
  ssh -p 22 alice@dev.example.com
  ```

- **Keepalive.** Каждые 15 секунд отправляется keepalive-запрос. Три пропущенных ответа подряд считаются обрывом соединения. Это ловит «мёртвые» соединения после выхода ноутбука из сна.

## Исключения: `.owysync/ignore`

Исключённые пути не загружаются на remote и не удаляются там. Исключённый каталог пропускается вместе со всем содержимым, с обеих сторон.

**Это не `.gitignore`.** Формат взят из dklab RealSync и намеренно проще, чтобы результат любой маски было легко предсказать.

**Формат файла**

- Текст в UTF-8, окончания строк CRLF допускаются.
- Одна маска на строку. Пробелы в начале и в конце строки отбрасываются.
- Пустые строки и строки, начинающиеся с `#`, пропускаются.
- `\` считается за `/`, так что можно писать пути по-виндовому.

**Два вида масок**

- **Маска имени** — без `/` и без `**`. Совпадает с **любым компонентом** пути на любой глубине: `node_modules` исключает `node_modules`, `a/node_modules` и всё внутри них.
- **Маска пути** — есть `/` в любом месте или `**`. Совпадает с путём **от корня** и со всем, что под ним. Ведущий `/` только делает маску маской пути: `/config.php` значит «только в корне».

Завершающий `/` (или `\`) отбрасывается **до** того, как определяется вид маски. Поэтому он не делает маску маской пути и не ограничивает её каталогами. `node_modules/` — та же маска имени, что и `node_modules`, и совпадает на любой глубине. `var/cache/` — та же маска пути, что и `var/cache`, из-за `/` в середине.

**Спецсимволы**

| Символ | Значение |
| --- | --- |
| `*` | Любые символы, кроме `/`, в том числе ни одного. Совпадает и с ведущей точкой: `*.log` исключает `.hidden.log` |
| `**/` | Ноль или больше каталогов: `**/tmp` совпадает с `tmp` и `a/b/tmp`; `a/**/b` — с `a/b` и `a/x/y/b` |
| `**` в остальных местах | Любые символы, включая `/`: `a/**` — всё внутри `a` |
| остальные | Сравниваются буквально и **с учётом регистра**. `[`, `]`, `!` (не в начале), `{` — обычные символы |

**Примеры**

| Маска | Исключает | Не исключает |
| --- | --- | --- |
| `node_modules` | `node_modules`, `web/node_modules/x.js` | `node_modules2` |
| `*.log` | `app.log`, `var/log/app.log`, `.x.log` | `app.log.1` |
| `~*` | `~$doc.docx`, `a/~lock` | `a~` |
| `/config.php` | `config.php` | `app/config.php` |
| `config.php` | `config.php`, `app/config.php` | `config.php.bak` |
| `var/cache` | `var/cache`, `var/cache/a/b` | `a/var/cache`, `var/cache2` |
| `var/cache/*` | всё внутри `var/cache` | сам каталог `var/cache` |
| `/*.log` | `app.log` в корне | `var/app.log` |
| `**/tmp/*.pid` | `tmp/a.pid`, `x/y/tmp/a.pid` | `tmp/sub/a.pid` |
| `[id].tsx` | `[id].tsx`, `pages/[id].tsx` | `i.tsx` |

**Отличия от `.gitignore`**

- Нет отрицания через `!`. Строка, начинающаяся с `!`, — ошибка.
- Нет `?` и диапазонов `[...]`. `?` в маске — ошибка: вместо `*.sw?` пишите `*.swp` и `*.swo`.
- `/` в середине привязывает маску к корню (как в git), и `**` тоже: `**/x` равнозначно `x`.
- Завершающий `/` не ограничивает маску каталогами и, как и в git, не привязывает её к корню: `build/` совпадает с `build` на любой глубине.
- Нет вложенных файлов исключений: есть только `.owysync/ignore`. `.gitignore` проекта не читается.

Пустая маска (например, `/`) или маска с компонентом `.` или `..` — тоже ошибка. В сообщении об ошибке указан номер строки, и синхронизация не запустится, пока ошибка не исправлена.

**Каталог `.owysync/`** есть с обеих сторон и никогда не участвует в синхронизации: его нельзя исключить, удалить или синхронизировать. Если на сервере за каталогом проекта следит watcher или веб-сервер, исключите в нём `.owysync/`.

Шаблон от `owysync init` исключает каталоги систем контроля версий (`.git`, `.svn`, `.hg`, `CVS`), каталоги IDE и временные файлы редакторов и Windows. В нём также есть закомментированные строки для `node_modules`, `vendor` и `*.log`.

## Что и как синхронизируется

- **Файлы и каталоги.** Отсутствующие создаются, изменённые файлы загружаются, объекты на remote, которых нет в local, удаляются. Если сменился тип (файл ↔ каталог), объект на remote удаляется и создаётся заново.
- **Время изменения.** После загрузки удалённому файлу выставляется mtime локального, поэтому расхождение часов между машинами не важно. mtime каталогов не синхронизируется.
- **Права.** Права существующих удалённых файлов сохраняются. Новые файлы получают `file_mode`, новые каталоги — `dir_mode`.
- **Атомарная замена.** Файл пишется во временный и затем переименовывается поверх целевого, поэтому читатели на сервере не видят недописанный файл. Для этого нужно расширение OpenSSH `posix-rename`. Без него файл на мгновение пропадает. Дерево в целом обновляется не атомарно.
- **Локальные symlink и junction** пропускаются с предупреждением и считаются исключёнными.
- **Удалённые symlink**, которых нет в local, удаляются как ссылки. То, на что они указывают, не затрагивается никогда.
- **Сокеты, FIFO и устройства на remote** (например, сокет php-fpm внутри проекта) не удаляются никогда. OwySync выводит предупреждение и предлагает добавить путь в `ignore`.
- **Каталоги с исключённым содержимым.** Если каталог, удалённый в local, на remote ещё содержит исключённые файлы, каталог остаётся вместе с ними, и OwySync печатает `kept directory ...`. Это не ошибка.
- **Недоступные удалённые каталоги.** Каталог на remote, который OwySync не может прочитать, не трогается вместе со всем содержимым, а остальное дерево синхронизируется. Resync помечается неуспешным, каталог называется в выводе. Если так и задумано, добавьте его в `ignore`.
- **Переименования** передаются как удаление и создание. Переименования только с изменением регистра (`Foo` → `foo`) работают так же: пути сравниваются с учётом регистра.
- **Пакетный режим.** Если в плане resync или в пачке live больше `bulk_threshold` загрузок или удалений (первая заливка, `git checkout`, большая сборка), OwySync упаковывает файлы в tar-архивы до 64 МБ, загружает их и распаковывает на сервере. Для этого в `.owysync/tmp` на сервере нужно до ~128 МБ свободного места. В пакетном режиме файлы пишутся на место, без атомарной замены.

## Вывод

Обычный вывод идёт в stdout:

```text
resync: started
resync: done in 2.4s: 100000 local files, 0 operations
+ src/new.php
~ src/changed.php
- src/removed.php
```

- `+` — создано, `~` — обновлено, `-` — удалено.
- Live-режим печатает каждую операцию. Полный resync печатает только строки начала и итога; с `-v` видна каждая его операция.
- `--dry-run` печатает операции, которые были бы выполнены, и итоговую строку `dry run: N operations, M bytes to upload; nothing changed`.

Предупреждения и ошибки идут в stderr с префиксами `warning:` и `error:`.

**Коды возврата:** `0` — успех; `1` — не прошла проверка, неуспешный resync (`--once`), прерывание или ошибка; `2` — неверные аргументы командной строки.

## Ошибки и восстановление

- **Не удалась операция с одним файлом** (файл занят редактором, нет прав): до 3 повторов с растущей задержкой, затем предупреждение. В live-режиме путь пробуется снова раз в 30 секунд. С `--once` код возврата ненулевой.
- **Обрыв соединения** (сетевая ошибка или три пропущенных keepalive): переподключение с растущей задержкой от 1 до 30 секунд, затем полный resync.
- **Remote изменили в обход OwySync:** это исправит следующий resync. Если live-режим сам наткнулся на такое изменение (например, на сервере удалили каталог), он запускает полный resync в фоне.
- **Ошибки конфигурации, аутентификации, отсутствие маркера:** OwySync сразу завершается с сообщением.
- **Защита от ошибки в `remote_root`:** OwySync отказывается синхронизировать в каталог без маркера `.owysync/remote`, поэтому опечатка в пути не сотрёт посторонний каталог.
- **Один экземпляр на каталог:** `.owysync/lock` не даёт запустить второй OwySync на том же локальном каталоге. Блокировка снимается при завершении процесса, даже аварийном.

## Ограничения

- **Сравнение по размеру и mtime — эвристика.** Если что-то на сервере перепишет файл тем же размером в ту же секунду, OwySync этого не заметит. Файл, изменённый на сервере, обычно получает другой mtime и перезаливается при следующем resync.
- **Регистронезависимые ФС на remote не поддерживаются** (FAT/exFAT, тома CIFS). Переименование вида `Foo` → `foo` может удалить только что загруженный файл.
- **Локальная сторона:** только Windows и только локальные диски.
- **Удалённая сторона:** Linux и FreeBSD с shell. macOS и учётные записи только с SFTP не поддерживаются.
- **SSH:** нет `~/.ssh/config`, паролей и Pageant.
- **Каждый запуск — полный resync.** Сохранённого индекса нет. На 100 тыс. файлов это несколько секунд.
- **Пути сравниваются побайтно.** Нормализации Unicode нет. Имена Windows с некорректным UTF-16 пропускаются с предупреждением.
- **Только в одну сторону.** Изменения, сделанные на сервере, обратно не копируются: они перезаписываются или удаляются.

## Решение проблем

| Сообщение или симптом | Что делать |
| --- | --- |
| `the directory is not initialized, run owysync init` | Выполните `owysync init` или укажите правильный путь |
| `host key: FAIL` | Подключитесь один раз через `ssh -p <port> <user>@<host>` и примите ключ |
| `authentication: FAIL` | Добавьте ключ в ssh-agent (`ssh-add`) или задайте `identity_file`. Ключ с паролем должен идти через агент |
| `shell: FAIL` | У учётной записи нет пригодного shell или нет `find`/`stat`/`tar`. Ограниченная оболочка или учётная запись только с SFTP не подойдёт |
| `marker .owysync/remote: FAIL` | Неверный `remote_root`, или удалённый каталог не инициализирован. Исправьте путь или выполните `owysync init --remote` |
| `? is not supported, use *` | Перепишите маску без `?` (например, `*.swp`, `*.swo`) |
| `not synced (no access): ...` | Удалённый пользователь не может читать эти каталоги. Исправьте права или добавьте их в `ignore` |
| `kept directory ...: it holds ignored files` | Информационное сообщение. Если каталог не нужен, удалите его на сервере сами |
| `warning: ... the changes take effect after a restart` | Вы изменили `config` или `ignore`. Перезапустите OwySync |
| Изменения не подхватываются | Убедитесь, что каталог на локальном диске, а не на сетевом и не в `\\wsl$` |
| Файл на сервере перезаливается снова и снова | Что-то на сервере его переписывает, или у локальной ФС грубые метки времени. Для FAT задайте `mtime_window = 2` |
